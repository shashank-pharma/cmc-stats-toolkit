# Sample data pack

Dummy data only, in exactly the CSV format of the UI templates, for trying the app and API.
Upload a file in the matching UI tab with the settings below. `expected.json` holds the same
settings and expected results in machine-readable form; `tests/test_sample_data.py` runs every
file through the UI parsing and core path and checks them (URS-GEN-004).

Educational and decision-support use only. Not validated for GxP use.

## Regenerating

```
uv run python sample_data/generate_samples.py   # stability and dissolution, writes generated_with.json
Rscript sample_data/generate_be.R               # BE, writes be_r_output.jsonl (R's own results)
uv run python sample_data/build_expected.py     # rebuilds expected.json from committed sources
```

Both generators are seeded and deterministic. The committed files were generated with
**numpy 2.5.4** (dissolution; recorded in `generated_with.json`) and **R version 4.6.1** (BE;
recorded in `be_r_output.jsonl`). Neither numpy nor R promises the same random stream across
releases, so another version may give different data. `expected.json` is never edited by hand:
`build_expected.py` makes it from the golden R outputs, `be_r_output.jsonl` and the core, and a
test checks that it reproduces the committed file exactly. After regenerating, review every
change in `expected.json` before committing; never change an expected value to make a test pass.

## Stability (tab: Stability)

Settings for all three: attribute Assay, unit % label claim, direction decrease, storage
condition **Room temperature**, lower limit 95.0, significant change at accelerated **No**, statistical analysis performed **Yes**.
B001 and B002 are the same in each file; only B003 differs. Months 0, 3, 6, 9, 12, 18, 24.
Expected values are independent R output (the same data as GOLD-STAB-001..003).

| File | B003 | Model | Governing batch | Crossing (months) | Shelf-life |
|---|---|---|---|---|---|
| `stability_b003_similar.csv` | similar to B001/B002 | pooled | none (one line) | 34.60 | 34 months |
| `stability_b003_start.csv` | lower start, same slope | common slope | B003 | 29.82 | 29 months |
| `stability_b003_faster.csv` | faster decline | separate | B003 | 24.33 | 24 months |

All three are capped at 36 months (Appendix A, X = 24). Refrigerated or freezer storage, or
significant change at accelerated, is refused as not supported in v1. Four known limitations
appear in the warning box on every stability result: only the room-temperature,
statistical-analysis branch of the Appendix A cap is supported (not the refrigerated 1.5X /
X + 6 branch), X is taken as the shortest batch coverage, the rules follow ICH Q1A(R2) and
Q1E, not the draft consolidated ICH Q1, and the golden cases are base R output on dummy data
(a published example is planned for v1.1). The separate-slopes result uses each
batch's own intercept and slope with the pooled mean square error of the full model
(df = N - 2k), ICH Q1E Appendix B.2.2.1. Up to 0.5.0 it used each batch's own error (24.62).

## Dissolution (tab: Dissolution)

12 units per product at 5, 10, 15, 20, 30 and 45 min, drawn with numpy `default_rng(20261028)`
as mean x (1 + CV x z), rounded to 2 decimals. Reference means 28 52 70 82 91 96.
Expected values are from this project's core (regression values, not an independent reference).

| File | Test means | Unit CV | Bootstrap settings | Expected |
|---|---|---|---|---|
| `dissolution_similar.csv` | 24 47 66 79 89 95 | 4% | none | CV limits met; 5 points used (85% cut-off at 30 min); f1 5.48, f2 69.76: **similar** |
| `dissolution_slow.csv` | 15 33 50 64 80 90 | 4% | none | CV limits met; all 6 points used; f1 20.21, f2 40.67: **not similar** |
| `dissolution_similar_high_cv.csv` | 24 47 66 79 89 95 | 15% (both products) | seed 20261028, 2000 resamples | CV limits fail at 20 and 30 min, so bootstrap f2 decides; mean f2 67.99; 5th percentile 50.99: **similar** (close to the limit) |

Running `dissolution_similar_high_cv.csv` without bootstrap settings is refused with a message
asking for a seed and resample count. The bootstrap method is provisional (Shah et al. 1998).

Known limitations shown in the warning box on every dissolution result with f1/f2 (all three
files): the 20% CV limit "at the earlier time points (e.g., 15 minutes)" is read as t <= 15 min;
f2 = 50 exactly is treated as similar ("f2 values greater than 50 (50-100)" read as inclusive);
f1/f2 are cross-checked against base R (`tests/golden/r/dissolution_gold.R`), with a published
example (Shah et al. 1998) planned for v1.1. When bootstrap f2 decides
(`dissolution_similar_high_cv.csv`), a fourth note says FDA 1997 does not describe bootstrap f2
and that the multivariate (MSD) method it names in section V.B is not in v1.

## Bioequivalence (tab: Bioequivalence)

Settings for both: design 2x2_crossover, limits average. Generated by `generate_be.R` with a
true T/R ratio of 0.97; the seed is the first from 1 upwards giving the stated outcome (seed 1
for both). Expected rounded 90% CIs are R's own output.

| File | Subjects (TR/RT) | Within-subject CV | Expected rounded 90% CI (Cmax; AUC0-t; AUC0-inf) | Expected |
|---|---|---|---|---|
| `be_24_subjects_cv20.csv` | 24 (12/12) | 20% | 88.05-105.94; 94.82-110.92; 94.57-110.52 | **bioequivalent** |
| `be_12_subjects_cv45.csv` | 12 (6/6) | 45% | 61.22-99.08; 59.27-99.79; 60.22-99.81 | **not bioequivalent** |

The CI rounding rule (half up) and whether AUC0-inf counts towards the decision are
placeholders pending confirmation against the target agency text, so the app shows them as
warnings.
